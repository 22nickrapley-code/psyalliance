# Concerns and pushback for Nick (running list)

Nick asked (26 Oct) that anything I would push back on, or keep from the original, in design, functionality or usability is raised at the end so it can be discussed. This list is added to as the port proceeds and is finalised in the hand-over report. Nothing here has been changed in the build without being listed; where a choice was needed to keep working, the default taken is stated.

| # | Area | Concern | Default taken meanwhile |
|---|------|---------|-------------------------|
| C-01 | Settings / account | The approved Settings window only offers Availability, Notification preferences and Preview controls. A real member also needs profile and licences, privacy, data export, account deletion, sign out, continuity plan, admin. None are in the mock-up. | Preview controls are removed in production (kept in demos). Extra rows added in the same row style, listed as EXC-01 for approval. |
| C-02 | Availability | The approved screen has no pause-until date, no separate Cover / Consult openness. Both exist today. | They stay on the existing Availability page, reachable from Settings. The Hub card does not show a pause. |
| C-03 | Availability copy | Copy says "After 90 days, we'll ask you to reconfirm", but reminder emails go out from day 30 today. | Reminder emails unchanged; copy unchanged. Your call. |
| C-04 | Vocabulary | The mock-up's insurer, modality and language lists differ from the product's controlled lists (28 vs 19 insurers, 40 vs 49 modalities). Session types are "Individual / Couples" in the mock-up and "Face to Face / Virtual" in the product. | Live screens use the product's lists, so what can be asked for is what profiles can carry. |
| C-05 | Worked with before | Today a consult reply counts as "worked with" in the database. The approved rules say messages and reactions alone must not. | Workspace uses cover agreed, confirmed referral placement and recorded completions only. Old pages' definition left alone. |
| C-06 | Design / navigation | The new screens and the pages not in the mock-up (profile editing, admin, documents, credentials) have two different shells. Moving between them is a full page load and looks like two products. | Accepted for now; recommend reskinning the remaining pages as a follow-up. |
| C-07 | Scale | The mock-up loads the whole directory into the browser and filters there. Fine for founding-cohort numbers; will not be at several thousand members. | Full list loaded now; paged server search is the follow-up. |
| C-08 | Engine | The approved UI is a 200 KB string-template script that re-renders whole pages. It reproduces the design exactly, but focus handling, screen-reader announcements and long-term maintainability are weaker than componentised code. | Kept as-is for fidelity. Accessibility checked in tests; findings listed. |
| C-09 | Messages | No live push; an open Messages screen asks for changes every 15 s (every 30 s elsewhere) and when you return to the tab. | Polling now; realtime is a later option. |
| C-10 | Keyboard hint | "⌘ K" is shown on Windows and phones where it does not apply. | Left as approved. |
| C-11 | Cover / Referrals eligibility | In the mock-up, an in-person need matches only a colleague's primary practice city. On the real product a colleague can hold a licence with a different city in another state. The server accepts either city. | Server rule is the union (primary city or the licence's city); the screens' own check is unchanged. Say if you want the stricter rule. |
| C-12 | Cover / Referrals copy | The mock-up toasts say "Delivery is simulated locally". Live screens drop that clause and show what really happened ("Cover requests sent", "N colleagues were not asked because they no longer match"). Colleagues see history lines of their own, written for them, that the mock-up never needed. | Listed as copy exceptions; no layout changes. |
| C-13 | Cover / Referrals privacy | In the mock-up every colleague could see who else was asked and who was placed. On the real product a colleague sees only their own request. For a placed referral, others see "placed with another colleague", never the name. | Enforced on the server, not only in the screens. |
| C-14 | Referrals: replying when licence lapsed | A colleague whose licence has lapsed cannot even decline (the existing rule blocks any reply). The referrer then sees that colleague as awaiting until they withdraw or ask someone else. | Existing rule kept. Recommend allowing a decline. |
| C-15 | Referrals: wide audiences | "The verified network" can mean hundreds of people notified at once. The server refuses more than 500 eligible colleagues in one referral. | Cap of 500; mock-up has none. |
| C-16 | Referrals: withdrawal notice | The mock-up says nothing about telling colleagues when a referral is withdrawn. Real colleagues would otherwise see a request vanish. | In-app notice (no email) to those still open. |
| C-17 | Messages: first-message menu | In the approved design the Edit / Remove menu on the first message of a conversation opens underneath the header strip and cannot be clicked (checked in the frozen mock-up itself). Real conversations open with a request line, but a direct conversation's first message is affected. | Kept exactly as designed; one-line fix (more room above the first message) is yours to approve. |
| C-18 | Messages: edit window | The product lets a message be edited for 15 minutes; the mock-up has no limit. Removing is always allowed. | Existing rule kept; the server's message is shown if you try later. |
| C-19 | Messages: long conversations | The mock-up never has more than a handful of messages. A real one can run to hundreds. | Latest 200 load; one extra "Show earlier messages" text button (not in the mock-up) loads 100 more at a time. Listed as EXC. |
| C-20 | Messages: files | Files and voice notes up to 20 MB, private to the two people. A file added and then dropped is removed; one lost to a closed tab stays in storage and shows up in the admin orphaned-files list after a day. | No automatic purge (same approach as photos and documents). |
| C-21 | Messages: hearts | The mock-up has one reaction (heart). The product also holds earlier like / dislike reactions; they are kept but no longer shown. A heart on a colleague's message adds them to Suggested for you, as in the mock-up; taking the heart back removes them again unless another reason keeps them there. | Heart only on screen. |
| C-22 | Messages: other pages | The old Messages page also carried the full notifications list and physician referrals (acknowledge / decline). The approved design has neither. | Both kept on their own pages (/dashboard/notifications, /dashboard/physician-referrals), reached from the bell and the what-needs-you list. Say if physician referrals should move into Referrals. |
| C-23 | Messages: date line | The mock-up always says "Today · <date>" above the messages. On real data that would be wrong for old conversations. | Shows the real day of the first message ("Yesterday", or the date). |
| C-24 | Messages: opening link | A conversation's address was one page per conversation; now /dashboard/messages?thread=<key>. Old links redirect. A conversation that is not selected is not in the address bar, so a reload opens the newest one. | Newest conversation selected on desktop; list on phones, as in the mock-up. |
